## 复盘 2026-10-28 · Flow v1.5.2 战役踩坑录

> 总病根一句话：改的是 A 文件，页面读的是 B 变量；且 SSH 通道悄悄啃碎中文字节。
> 两条铁律：① SSH 只传纯 ASCII，含中文文件一律 GitHub 网页编辑器；
> ② 「改了没生效」先查数据接线，再查缓存，最后才怀疑部署。

### 一、数据接线类
1. **渲染引擎读私有数据（本案总根因）**
   症状：flow-prompts.js 反复更新部署，Flow 页永远旧四团。
   根因：nova-flow.js 自带 `const NF_TEAMS/NF_STAGES`，从不读 window.FLOW_TEAMS。
   修复：`const NF_TEAMS = window.FLOW_TEAMS || [旧数据兜底]`。
   预防：改配置前先 grep **消费方的变量名**，不只看文件名；const 与全局 var 撞名会
   SyntaxError，不能直接改名，要用「别名+兜底」接线。
2. **扫描定义漏掉读取**：赋值正则扫不到「读全局」的用法。全貌 = VAR map + token map
   双扫描，缺一不可。

### 二、编码与传输类
3. **SSH 粘贴啃 CJK 字节（惯犯）**
   症状：浏览器宽容照常跑，Python 严格解码报 UnicodeDecodeError
   （0xed / 孤儿 \xe5 / 拆字 \x96\xb9），ASCII 指纹能过所以长期潜伏。
   受害者：flow-prompts.js、flow.html@4015（全流程按钮）、nova-flow.js@4064（；方式）。
   修复：字节级精确替换；全仓体检脚本扫 OK/BAD。
   预防：heredoc 里中文一律 \uXXXX 转义；文件级中文走网页编辑器。
4. **直览 .js 乱码假警报**：Content-Type 无 charset → 浏览器瞎猜编码。
   修复：_headers 给 /js/* 加 charset=utf-8。教训：乱码≠文件坏，先分清
   「字节坏了」还是「显示猜错」。
5. **聊天/终端复制也可能丢字节**：out-box「截断」实为复制丢字。
   以文件字节检查为准，不信视觉转述。

### 三、流程与工具类
6. **网页编辑残留旧行**：插新行没删净旧行（settings 145/146/151）→ 内置档案双份按钮
   +非法停用/删除。预防：手改生成型 JS 后打印整块上下文核对；删行前 assert 行内容。
7. **可选 DOM 未守卫 → settings 白屏**：`var tg=…; if(tg)tg.onclick=…`。
   条件渲染的元素，事件绑定必须判空。
8. **push 中断 ≠ 提交丢失**：^C 只断等待，本地提交还在，git log 确认后重推。
9. **服务端脚本当不了线上法官**：四连 False 差点误判翻车，实为 CF 机器人防护 403
   + 内网外联飘。预防：诊断脚本必须打印失败原因而非裸布尔；线上裁决以浏览器为准；
   不为脚本关防护。
10. **诊断脚本先 assert 后动手**：flow.html 补丁因假设不成立自动拒打，避免错误修改。
    此纪律保留为标准写法。
